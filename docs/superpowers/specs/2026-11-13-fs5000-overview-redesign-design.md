# FS-5000 통합 화면 개편 설계

- 날짜: 2026-11-13
- 대상: Bosean FS-5000 (`env:bosean-fs5000-ko`), 브랜치 `develop` 기준
- 승인된 시안: `docs/mockups/overview-v4.html` (통합 화면 1·2쪽, 상단 바). 좌표·색·글꼴 크기는 이 파일이 기준이다.
- 이전 시안: `overview-v2.html`, `overview-v3.html` (비교용, 구현 대상 아님)

## 1. 왜 하는가

FS-5000 측정 화면은 지금 다섯 개(통합·순간·평균·누적·추이)를 좌우 키로 넘긴다. 사용자는 통합 화면과 그래프만 있으면 된다고 판단했다. 현재 통합 화면에는 누적 카운트, 측정 시작 시각, 경과 시간이 없다. 상단 바는 48 px을 쓰면서 "측정"과 시각만 보여준다.

목표는 **측정 화면 하나에 두 쪽**을 두는 것이다.

- 1쪽: 한눈에 보는 값 (순간 선량률, 막대, 평균·최대·누적 선량·카운트, 시작·경과)
- 2쪽: 그래프 중심 (작은 순간·평균·보조 단위 값, 평균 시간·신뢰구간, 큰 추이 그래프)

## 2. 목표 / 비목표 / 실패 조건

목표
- 승인 시안(v4)과 같은 배치·글꼴 크기·색으로 실기에서 보인다.
- 다른 측정 화면을 없애도 그 화면에만 있던 정보와 동작(평균 시간·신뢰구간, 보조 단위, 누적 초기화)을 잃지 않는다.
- 한국어 빌드가 `FIRMWARE_SIZE=0x18000`(98,304 B, R5) 안에 들어간다. 지금 65,552 B, 여유 32,752 B.

비목표
- 다른 기기(GMC-800 등 `DISPLAY_240X320` 공유 기기, 320×240 기기)의 화면 변경. **모든 변경은 `FS5000` 조건 안에 둔다.** 다른 기기의 빌드 결과는 바뀌지 않아야 한다.
- 한국어 외 언어의 번역과 빌드. 사용자 결정: **한국어 펌웨어만 빌드한다.** `tools/build-env.py`에서 FS-5000 환경은 `ko`만 만들도록 줄인다(다른 기기 환경은 그대로). 새 글꼴도 한국어용만 만든다. 새 문자열은 소스 컴파일을 위해 모든 언어 파일에 넣되 한국어·영어만 제대로 쓰고 나머지는 영어 문장을 넣는다. 중국어·일본어 FS-5000 빌드는 플래시가 모자랄 가능성이 커서 대상에서 뺀다(빌더 판단).
- 리뷰 레포트의 남은 결함(#6~#10) 수정.

실패 조건 (동작해도 실패로 본다)
- 이전 화면 내용이 지워지지 않고 남는 빈틈(이 펌웨어는 지우기 단계가 없다. 그린 사각형만 덮인다).
- 글자가 잘리거나 서로 겹친다. 특히 상단 바, 시작·경과 줄, 2쪽 값 칸.
- 메뉴·통계·게임·난수 등 다른 화면이 상단 바 변경으로 깨진다.
- 단위 접두어(µ/m)가 바뀌었는데 화면에 표시가 없어 값을 1000배 잘못 읽게 된다.

## 3. 화면 사양

좌표는 240×320 세로 화면 기준이다. 정확한 픽셀은 `overview-v4.html`의 인라인 `style`(top/left)을 따른다. 빌더가 실제 글꼴 메트릭에 맞춰 ±2 px 조정하는 것은 괜찮다.

### 3.1 글꼴

| 이름 (제안) | 크기 | 내용 | 용도 |
|---|---|---|---|
| `font_tiny` (새, 한국어용만) | 14 px, Noto Sans KR SemiBold | **아래 3.6의 문자열에 쓰인 글자 + 숫자·기호만** (부분 집합) | 상단 바, 시작·경과 줄, 막대 눈금, 2쪽 칸 라벨·보조 줄, 그래프 축 글자 |
| `font_small` (기존) | 21 px | 한국어 전체 문자열 글자 (새 문자열 반영해 재생성) | 1쪽 값 줄, 2쪽 값 숫자, 메뉴 등 기존 용도 |
| `font_value` (새) | 54 px, 숫자 전용 (`CODEPOINT_SET_LARGE`와 같은 글자) | | 1쪽 순간 선량률 |
| `font_large` (기존 84 px) | | | 난수 화면이 계속 쓰므로 유지 |
| 상단 바 아이콘용 기호 글꼴 (새) | 상단 바 23 px 안에 들어가는 크기 (약 16 px) | `CODEPOINT_SET_SYMBOLS_COLOR` | 상단 바의 경보·배터리·잠금·소리 아이콘. 전원 끔 화면 등 다른 곳은 기존 24 px 기호 글꼴 유지 |

- 글꼴은 `tools/build-fonts.py`의 `run_fontconv`로 만든다(임의 글자 집합·픽셀 지정 가능). 이 PC에서는 PyPI 접속이 되므로 `freetype-py`, `bdflib`를 venv에 설치해 정식 도구를 쓴다.
- `build-fonts.py`는 전 언어 글꼴을 다시 만든다. FreeType 버전 차이로 다른 언어 파일이 바뀌면 **한국어 파일과 새 글꼴 파일만 남기고 나머지 변경은 되돌린다.**
- 새 글꼴의 빌드 연결: `tools/build-env.py`가 FS-5000 환경에 새 매크로(예: `FONT_TINY`, `FONT_VALUE`, `FONT_SYMBOLS_SMALL`)를 넣고 `platformio.ini`를 다시 만든다. 하네스(아래 6절)도 같은 매크로를 쓴다.
- 줄 끝은 CRLF다. 생성 파일도 저장소 규칙에 맞춘다.

### 3.2 상단 바 (FS-5000의 모든 화면)

- 높이 24 px(내용 23 px + 그림자 1 px). `TITLEBAR_HEIGHT`를 FS-5000에서만 24로 바꾼다. 그 결과 `CONTENT_TOP`·`CONTENT_HEIGHT`가 바뀌므로 메뉴·통계·게임·난수·알림 화면을 렌더링해 확인한다(6절).
- 글꼴 `font_tiny`. 아이콘은 작은 기호 글꼴.
- **측정 화면**: 왼쪽에 `시:분`(기존 12/24시간 설정 따름), 10 px 띄우고 순간 평균 방식 문자열(`STRING_ADAPTIVE_FAST` 등 `settings.instantaneousAveraging`에 해당하는 것, 색 neutral). 오른쪽에 아이콘(소리·잠금·경보·배터리, 기존 순서와 조건 그대로). 날짜는 넣지 않는다.
- **그 밖의 화면**: 왼쪽에 화면 제목, 오른쪽에 아이콘과 `시:분` (지금과 같은 구성, 글꼴만 작아짐).
- 아이콘이 모두 켜져도 "적응형 (정밀)"까지 들어간다(시안 확인). 그래도 넘치면 평균 방식 문자열을 생략한다.

### 3.3 통합 화면 1쪽 (시안 "1쪽 · 값")

위에서부터:
1. 순간 선량률 54 px 숫자, 왼쪽 정렬(x=12). 색은 기존 `getInstantaneousRateMeasurementStyle()` 결과(경보 시 빨강 등).
2. 숫자 오른쪽 위에 단위(21 px, neutral, 오른쪽 정렬 x=228), 그 아래 신뢰구간 `±12%`(14 px, 값 색).
3. 로그 막대: 10배 눈금 글자(`1 µ`, `1 m`, 14 px) → 눈금 → 18 px 막대. 튜브 고장이면 이 자리에 `STRING_ALERT_FAULT`를 기존처럼 표시.
4. 값 줄 4개 (21 px, 줄 높이 30): 평균, 최대, 누적 선량, 카운트. 라벨 neutral 왼쪽, 값+단위 오른쪽. 평균이 끝난 상태(평균 타이머 종료)면 평균 값을 기존 DONE 스타일 색으로.
5. 시작·경과 한 줄 (14 px): 왼쪽 `시작 MM.DD HH:MM`, 오른쪽 `경과 H:MM:SS`(`strcatTime`). 라벨 neutral, 값 active.
6. 맨 아래 쪽 표시 점 2개(6×6 px, 간격 6 px, 가운데, y=302). 현재 쪽은 active 색, 다른 쪽은 frame-line 색.

색 규칙(빌더 판단): 누적 선량 값은 기존 누적 화면과 같은 스타일(`getCumulativeDoseMeasurementStyle()`: 경고·경보·포화)로 칠한다. 선량 경보가 울려 1쪽으로 넘어오면 이 줄 색으로 이유가 보인다. 평균 값은 평균이 끝났으면 DONE 스타일 색. 평균 종료 시 울리는 기존 알림음은 그대로 둔다.

### 3.4 통합 화면 2쪽 (시안 "2쪽 · 그래프")

1. 값 칸 세 개: 라벨(14 px, neutral) 아래 값(21 px).
   - 순간: 값 색 강조. 평균: active. 셋째 칸: 순간 선량률을 **보조 단위**(`settings.secondaryDoseUnits`)로 표시, 오른쪽 정렬.
   - **라벨에 단위를 붙인다**: `순간 µSv/h`, `평균 µSv/h`, 셋째 칸 라벨은 보조 단위 이름(`cpm` 등). 값의 접두어가 바뀌면(예: mSv/h) 라벨 단위도 같이 바뀐다. (시안의 "순간"/"평균"에서 바꾼 부분. 접두어를 놓치지 않게 하려는 빌더 판단.)
   - 칸 x: 12, 96, 오른쪽 정렬 228 (시안 그대로).
2. 보조 줄 (14 px): 왼쪽 `평균 시간 H:MM:SS`, 오른쪽 평균 신뢰구간 `±3.8%`. 튜브 고장이면 이 줄 왼쪽에 `STRING_ALERT_FAULT`(경보 색)를 대신 표시한다.
3. 그래프 (3.5절). 폭 201 px(데이터 칸 수 `HISTORY_BIN_NUM` 그대로), 높이 약 176 px, x=13.
4. 시간축 줄 (14 px): 왼쪽 `◀ 기간 ▶`(삼각형은 사각형으로 그린 5×6 px 도형), 그래프 가운데에 절반 시점 문구, 오른쪽 `지금`.
5. 맨 아래 쪽 표시 점 2개(둘째가 켜짐, y=308. 시안 그대로).

### 3.5 그래프 사양

기존 `drawHistory`(기간별 칸 데이터 `logValues`, 경고·경보 색 칠하기)를 바탕으로, FS-5000용으로 위치·높이를 받는 그리기 함수를 만든다(기존 함수는 다른 기기용으로 남긴다).

- **세로 범위**: 지금은 10배 단위로 잡는다. FS-5000에서는 **1·2·5 단위**(…, 0.05, 0.1, 0.2, 0.5, 1, 2, 5, …)로 잡는다. 아래 끝은 데이터 최솟값 이하의 가장 큰 1·2·5 값, 위 끝은 데이터 최댓값보다 여유를 둔 1·2·5 값. 데이터가 없으면 기존처럼 빈 그래프.
- **가로선**: 범위가 약 1.5 decade 이하면 1·2·5 값마다, 넘으면 10배 값마다 긋는다. 선 사이가 18 px보다 좁아지면 한 단계씩 건너뛴다. 선은 데이터 칠한 면 **위에** 점선(tick 색)으로 보이게 그린다.
- **가로선 값**: 각 선의 왼쪽 위에 14 px로 적고, 글자 뒤는 frame 색으로 덮는다(펌웨어 글자 그리기가 사각형을 채우므로 자연스럽다). 맨 위 값에만 단위를 붙인다(`1 µSv/h`). 모든 값은 맨 위 값과 같은 접두어로 쓴다(`0.5`, `0.05`). 소수 셋째 자리를 넘으면 그 값은 생략한다.
- **경고선**: 선량률 경고(`settings.rateWarning`)가 켜져 있고 범위 안이면 그 값에 경고 색 점선과 오른쪽에 `경고`(14 px, 경고 색). 경보선(`rateAlarm`)도 같은 방식으로 `경보`(있는 문자열 재사용 가능하면 재사용). 경고·경보 넘는 부분 색칠은 기존 동작 유지.
- **현재 점**: 마지막 칸 값 위치에 지름 약 7 px 점(값 색, 테두리 frame 색). 원이 어려우면 5×5 사각형도 괜찮다(빌더 판단).
- **세로 눈금선**: 기존 `timeTicksNum` 그대로.
- **오른쪽 눈금**: 가로선 위치에 짧은 눈금(기존 스타일).
- 기간 전환: 10분 → 1시간 → 1일 → 1주 → 1개월 → 1년 (기존 `histories[]`).

### 3.6 새 문자열

모든 언어 파일(`platform.io/src/system/strings/*.h`, 30개)에 넣는다. 한국어 / 영어:

| 매크로 (제안) | ko | en |
|---|---|---|
| `STRING_CUMULATIVE_DOSE` | 누적 선량 | Cumulative dose |
| `STRING_START` | 시작 | Start |
| `STRING_ELAPSED` | 경과 | Elapsed |
| `STRING_AVERAGE_TIME` | 평균 시간 | Average time |
| `STRING_NOW` | 지금 | Now |
| `STRING_WARNING` | 경고 | Warning |
| `STRING_ALARM` (없으면) | 경보 | Alarm |
| `STRING_HISTORY_HALF_10_MINUTES` … `_1_YEAR` | 5분 전 / 30분 전 / 12시간 전 / 3.5일 전 / 14일 전 / 6개월 전 | 5 min ago / 30 min ago / 12 h ago / 3.5 d ago / 14 d ago / 6 mo ago |
| `STRING_NOTIFICATION_CUMULATIVE_RESET_CONFIRM` | 누적 선량을 초기화하시겠습니까?\n\n선량, 카운트, 시작 시각이 지워집니다. | Reset cumulative dose?\n\nDose, counts and start time will be cleared. |
| `STRING_NOTIFICATION_CUMULATIVE_RESET_SUCCESS` | 누적 선량을 초기화했습니다. | Cumulative dose reset. |

이미 같은 뜻의 매크로가 있으면 재사용한다. `font_tiny`의 글자 집합은 상단 바·시작경과·2쪽·그래프에 쓰이는 문자열(평균 방식 5종, 위 표의 시작·경과·평균 시간·지금·경고·경보·기간·절반 시점, `STRING_ALERT_FAULT`, 화면 제목으로 쓰이는 모든 메뉴 제목 문자열, 단위 문자열)과 `0x20-0x7e`, `±µ`에서 뽑는다. **화면 제목이 상단 바에 나오므로 메뉴 제목 문자열 전부가 들어가야 한다**는 점에 주의(빠지면 글자가 비어 보인다).

## 4. 동작 사양

### 4.1 화면 구성과 키 (FS-5000)

- 측정 화면 순환(`measurementViews[]`)에는 통합 화면 하나만 둔다. 순간·평균·누적·추이 뷰는 FS-5000에서 등록하지 않는다(코드는 다른 기기용으로 남는다).
- 측정 모드 키(3키):
  - OK 짧게(`EVENT_KEY_BACK`): 1쪽 ↔ 2쪽.
  - 2쪽에서 왼쪽 짧게(`EVENT_KEY_UP`) / 오른쪽 짧게(`EVENT_KEY_DOWN`): 그래프 기간 이전 / 다음(순환).
  - 1쪽에서 왼쪽·오른쪽 짧게: 아무 동작 없음. (공통 처리 `onMeasurementViewEvent`가 뷰를 다시 그리기만 하게 두거나, 통합 화면이 먼저 받아 무시한다.)
  - 왼쪽 길게(`EVENT_KEY_RESET`): **순간값·최대값·평균**을 초기화한다(경보 해제가 우선인 기존 동작 유지). 누적 선량과 그래프는 지우지 않는다.
  - 오른쪽 조금 길게(설정), OK 길게(전원), 두 키 조합(잠금·소리)은 그대로.
- 쪽 번호와 그래프 기간은 전원을 켤 때 1쪽·10분으로 시작한다(설정에 저장하지 않음).
- 화면이 꺼진 상태에서 경보가 울려 화면이 켜지면 통합 화면 **1쪽**으로 간다(`updateMeasurements`의 자동 전환).

### 4.1a 없어지는 정보 (빌더 판단)

다음은 빼는 화면에만 있던 값이지만 통합 화면에 넣지 않는다: 평균의 보조 단위 값, 평균 기간 펄스 수, 누적 선량의 보조 단위 값(보조 단위가 cpm이면 1쪽 카운트와 같다). 평균 시간, 평균 신뢰구간, 순간 보조 단위는 2쪽에 남긴다.

### 4.2 누적 선량 초기화

- 설정 > 측정 메뉴에 `누적 선량` 항목을 추가하고, 그 안에 `초기화`(`STRING_RESET`)를 둔다. 선택하면 데이터 로그 초기화와 같은 확인 화면(`STRING_NOTIFICATION_CUMULATIVE_RESET_CONFIRM`) → 확인 시 초기화하고 완료 알림.
- 초기화하면 누적 선량(시간·카운트)과 시작 시각을 함께 지운다. 시작 시각은 초기화한 순간의 기기 시각으로 기록한다.

### 4.3 시작 시각

- 지금은 누적 경과 초(`cumulative.dose.time`, 측정한 동안만 증가)만 저장한다. 시작 시각을 저장하는 32비트 값을 `State`(`system/settings.c`)에 FS-5000 한정으로 추가한다.
- `SETTINGS_VERSION`은 `system/system.h:19`의 전역 정의다. `#if defined(FS5000)` 분기를 새로 두고 다른 바이트열을 쓴다. `State`는 8바이트 정렬이라 4바이트 필드가 기존 패딩에 들어가 크기가 그대로일 수 있지만, `saveSettings`가 초기화하지 않은 스택 변수의 패딩까지 쓰므로(`settings.c:217`) 옛 기록에서는 시작 시각이 쓰레기 값으로 읽힌다. 그래서 버전은 반드시 바꾼다(옛 설정은 초기화된다. 이번 설치는 mass erase라 어차피 초기화된다).
- 저장 값은 `getDeviceTime()`과 같은 기준. 표시할 때 기존 시간대 변환으로 지역 시각 `MM.DD HH:MM`(12시간제 설정이면 상단 바와 같은 규칙).
- RTC가 설정되지 않았거나(`year < RTC_YEAR_MIN`) 값이 0이면 `--`로 표시한다. 최초 부팅(저장된 상태 없음) 때도 그 시점 기기 시각을 시작 시각으로 둔다.
- 경과는 측정 시간(`cumulative.dose.time`)이다. 기기를 끈 동안은 늘지 않으므로 "시작 + 경과 = 지금"이 아닐 수 있다(의도된 동작).
- 저장 시점은 기존과 같다(정상 전원 끄기 때 `saveSettings`).

## 5. 구현 메모 (빌더 참고)

- 현재 통합 화면: `measurements/instantaneous.c`의 `onOverviewViewEvent`·`drawOverviewView`, 그리기 보조는 `ui/measurements.c`의 `drawMeasurementOverview*`. 핸드오프 문서 `docs/handoff/2026-11-12-fs5000-handoff.md`의 "화면 그리기" 절을 먼저 읽는다(지우기 없음, 사각형 채우기 규칙).
- 평균 값·시간·신뢰구간·완료 여부는 `measurements/average.c`의 static이다. 필요한 접근 함수를 추가한다.
- 그래프 데이터는 `measurements/history.c`의 `historyStates[]`, 그리기는 `ui/history.c`. 기간 상태(`historyTab`)를 통합 화면에서 바꿀 수 있게 접근 함수를 둔다.
- 측정 화면 키 매핑은 `peripherals/keyboard.c`의 `KEYBOARD_3_KEYS` 절.
- 주석은 사용자 허가 없이 추가하지 않는다(사용자 전역 규칙). 기존 코드 스타일(중괄호 줄바꿈, 4칸 들여쓰기, CRLF)을 따른다.

## 6. 검증

1. **빌드**: `~/.radpro-pio/Scripts/pio run -e bosean-fs5000-ko` (작업 폴더 `platform.io`). 경고 0, 플래시 사용량 ≤ 98,304 B (`0x18000`, R5). 결과 크기를 보고에 적는다.
2. **다른 기기 무변경**: GMC-800 정의(`DISPLAY_240X320`, `DISPLAY_125PPI`, `VOICE`)와 320×240 정의로 바뀐 파일을 문법 검사한다(이 PC의 WinLibs `gcc -fsyntax-only`). 가능하면 `pio run -e gq-gmc800-en`도 빌드해 성공을 확인한다.
3. **PC 렌더링**: `docs/handoff/attachments/harness/harness.c`를 이 PC(Windows, WinLibs gcc)에서 돌도록 고친다. 새 글꼴 매크로 반영. 다음을 PPM→PNG로 저장하고 시안과 나란히 비교한다.
   - 1쪽, 2쪽(10분·1주), 낮/저녁/밤 테마, 평상시/경보, 튜브 고장
   - 상단 바: 평상시, 고정 평균(10초), 아이콘 모두 켜짐
   - 메뉴 한 화면, 통계, 게임, 난수, 알림(누적 초기화 확인) 화면
   - 하네스는 화면을 자홍색으로 먼저 칠한다. 자홍색이 남으면 빈틈이다.
4. **실기**: 서명(`tools/sign.py`) 후 `build/radpro-3.1.1/bosean-fs5000/install.bat <서명된 이미지 절대경로>`로 올린다(작업 폴더 `build/radpro-3.1.1/bosean-fs5000`). ST-Link 필요. 스크립트가 백업 후 mass erase한다. 올린 뒤 쪽 전환, 기간 전환, 길게 누르기 초기화, 누적 초기화 메뉴, 배터리 전압(멀티미터 비교)을 사용자와 확인한다.
