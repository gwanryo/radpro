Bosean FS-5000에 Rad Pro를 올리기 전에 한 코드 리뷰, 통합 화면 추가, 한국어 번역 수정을 다음 사람이 이어받을 수 있게 정리한다.

## 사용자가 내린 결정

- 레포트는 저장소 사본만 둔다. 옵시디언·사내 wiki에는 올리지 않는다.
- 통합 화면은 시안 A(계기판)로 한다.
- 번역 제안은 불감시간 두 항목(`데드 타임`, `데드 타임 보상`)만 빼고 모두 반영한다.

아직 답을 받지 못한 것: 통합 화면의 막대를 시안처럼 가운데로 옮길지.

## 리뷰에서 알게 된 것

레포트에 전부 있다. 이어받는 사람이 꼭 알아야 할 것만 추린다.

- **태그 `3.1.1`이 아니라 HEAD를 올린다.** 태그에는 데이터 로그 결함 네 건이 남아 있고 `0275cb3`에서 고쳐졌다.
- HEAD에도 남은 major: 다운로드 중 USB 분리 시 로깅 정지, 고정 평균 모드 거짓 경고, 펄스가 끊겨도 이전 선량률 유지, 설정 페이지 교체 중 전원 차단 시 초기화, 튜브 카운트 초기화 시 로그에 거대한 증분, 기준 항목 부분 기록.
- `tools/sign.py`로 서명한 이미지만 올린다. 서명이 없으면 매번 체크섬 오류 화면이 뜬다.
- 영어 빌드(`FIRMWARE_SIZE=0xd000`)와 한국어 빌드(`0x14000`)는 설정·로그 주소가 다르다. 언어를 바꿔 올리면 설정과 누적값이 초기화된다.
- 플래싱 직후 통계 화면의 배터리 전압을 멀티미터와 비교한다(ADC 기준전압 채널 순서를 문서로 확정하지 못했다).

리뷰 방법: 리드가 전체를 읽고, Opus·Sonnet·Codex가 독립 리뷰한 뒤 서로의 발견을 반증했다. 레포트의 "검증" 열이 그 결과다. "단독" 표시 항목은 다른 리뷰어의 반증을 거치지 않았다.

## 코드베이스에서 알게 된 것

### 빌드 구성

- FS-5000 정의: `FS5000`, `DISPLAY_COLOR`, `DISPLAY_240X320`, `KEYBOARD_3_KEYS`, `BUZZER`, `VIBRATOR`, `PULSE_LED`, `ALERT_LED`, `GAME`, `BOOTLOADER`, `USB_AUTOPOWER_ON`. USB는 쓰지 않고 USART1이다.
- FS-5000에서 컴파일되지 않는 것: `EMFMETER`, `VOICE`, `PULSESOUND_ENABLE`, `TUBE_HV_PWM`, `BATTERY_REMOVABLE`, `LED_MULTIPLEX`.
- `DISPLAY_240X320`은 FS-5000 외에 GMC-800 계열(`DISPLAY_125PPI` 추가, `VOICE` 있음)도 쓴다. 이 가드 안의 코드는 그 기기에도 들어간다.
- `platformio.ini`는 `tools/build-env.py`가 `tools/platformio.ini.base`에서 만든다.
- 플래시 배치(영어 빌드): 펌웨어 `0x08000000–0x0800CFFF`, 설정 1페이지 `0x0800D000`, 로그 `0x0800D800–0x0803FFFF`. 페이지 2 KB, 쓰기 단위 8바이트.

### 소스 파일 규칙

- **줄 끝이 CRLF다.** 파이썬으로 고칠 때 `newline=''`로 열지 않으면 파일 전체가 바뀐 것으로 잡힌다. 고친 뒤 `git diff --stat`으로 줄 수를 확인한다.
- 주석은 사용자 허가 없이 추가하지 않는다(사용자 전역 규칙).

### 실행 구조

- SysTick 1 kHz가 `onTick()`을 부른다. 펄스 집계, 키 스캔, 부저·진동·LED 타이머가 여기서 돈다.
- 1초마다 하트비트. 메인 루프의 `updateEvents()`가 하트비트를 보고 `updateMeasurements()` → 화면 갱신을 한다.
- 메인 루프가 인터럽트와 공유하는 값을 건드릴 때는 `syncTick()`으로 틱 직후에 맞춘다. 이게 경쟁을 막는 유일한 장치다.
- `NVIC_SetPriority`에 넘긴 값이 잘려 인터럽트 우선순위는 모두 0이다(레포트 #11).
- 설정·누적 선량·튜브 수명은 **정상 전원 끄기 때만** 저장된다(`power.c:239`).

### 화면 그리기

- 지우기 단계가 없다. **텍스트를 그리면 그 사각형 전체가 배경색으로 채워진다.** 화면을 만들 때는 내용 영역을 사각형으로 빈틈없이 덮어야 한다. 빈틈은 이전 화면이 남는다.
- 글꼴은 세 크기뿐이다: 큰 숫자(84 px, 숫자·마침표·대시만), 중간(32 px, 단위 문자만), 작은(21 px, 그 언어 문자열에 나온 글자만).
- 글꼴은 **문자열에 쓰인 글자만 담는다.** 문자열을 바꾸거나 추가하면 그 언어 글꼴을 다시 만들어야 한다. 새 문자열은 모든 언어 파일(`strings/*.h`)에 넣어야 빌드된다.
- 세로 화면 내용 영역은 y 48~320이다. 기존 막대(`drawMeasurementBar`)는 위치가 매크로로 고정되어 y 256~320에만 그린다.
- 측정 화면에서 키: 왼쪽 짧게=이전 뷰, 오른쪽 짧게=다음 뷰, OK 짧게=탭 넘기기, 왼쪽 길게=초기화, 오른쪽 조금 길게=설정, OK 길게=전원.

## 통합 화면 구현 메모

위에서부터 순간 선량률 큰 숫자, 신뢰구간(왼쪽)과 단위(오른쪽), 평균·누적·최대 세 줄, 로그 막대. 튜브 고장일 때는 막대 자리에 고장 문구.

| 결정 | 이유 |
|---|---|
| 뷰를 `instantaneous.c` 안에 둠 | 신뢰구간·최대값·경보 스타일이 그 파일의 static이라 새 접근 함수를 만들지 않아도 된다 |
| 제목에 `STRING_MEASUREMENTS` 재사용 | 새 문자열을 만들면 전 언어 파일과 글꼴을 고쳐야 한다 |
| 막대를 맨 아래에 둠 | 기존 막대 함수를 건드리지 않으려고. 시안 A는 막대가 가운데다 |
| 줄 위치를 `BAR_TOP`에서 거꾸로 계산 | 글꼴 줄 높이가 다른 `DISPLAY_125PPI`에서도 빈틈이 없다 |
| 기본 뷰를 `viewIndex = 0`으로 | 240×320이 아닌 기기는 0번이 기존 순간 화면이라 동작이 그대로다 |
| 길게 누르기는 순간값·최대만 초기화 | 순간 화면과 같은 동작. 평균·누적은 각자 화면에서 지운다 |

경보가 울려 화면이 꺼진 상태에서 자동으로 넘어가는 뷰는 여전히 순간 화면이다(`measurements.c`의 `setMeasurementViewSelect`).

Sonnet이 별도 리뷰했고, 음성 키·초기화 키 누락과 막대 코드 중복을 반영했다.

## 번역과 글꼴

바뀐 문자열은 `git diff -- platform.io/src/system/strings/ko.h`로 본다. 주요 변경: 즉시→순간, 속도→선량률, 기록→추이, 회→카운트, 신뢰도→신뢰구간, 절전→화면 꺼짐.

반영하지 않고 남긴 것: `STRING_NOTIFICATION_HVCUSTOM`의 "장치"(다른 곳은 "기기"). FS-5000에서는 표시되지 않는 문자열이다.

글꼴은 정식 도구로 만들지 못했다.

- `tools/build-fonts.py`는 `freetype-py`와 `bdflib`가 필요한데 PyPI 접속이 타임아웃이었다(`curl: (28) Connection timed out`).
- 대신 Homebrew의 `libfreetype`을 ctypes로 부르는 임시 모듈(`attachments/fontgen/shim/freetype.py`)을 만들어 한국어 컬러 글꼴만 생성했다.
- 원래 `ko.h`로 같은 방법을 돌려 보면 저장소 글꼴과 바이트가 다르다. 줄 높이·ascent 같은 수치는 같고 테두리 픽셀이 다르다. FreeType 버전 차이로 추정하며 확인하지 못했다.
- **흑백용 한국어 글꼴(`font_*_ko_monochrome.h`)은 다시 만들지 않았다.** 흑백 기기 한국어 빌드에서는 새 글자가 빠진다.

정식으로 다시 만들려면:

```sh
pip install freetype-py bdflib
cd tools && python build-fonts.py
```

이 명령은 전 언어 글꼴을 다시 만든다. FreeType 버전이 원작자와 다르면 다른 언어 글꼴도 바뀐 것으로 잡힌다.

임시 도구로 한국어 컬러 글꼴만 만들려면:

```sh
python3 docs/handoff/attachments/fontgen/gen.py "$PWD" ko platform.io/src/system/strings <출력 폴더>
```

출력은 LF 줄 끝이므로 저장소에 넣기 전에 CRLF로 바꾼다. shim의 라이브러리 경로는 `/opt/homebrew/opt/freetype/lib/libfreetype.6.dylib`로 고정되어 있다.

## PC에서 화면 확인하는 법

SDL 시뮬레이터를 빌드할 수 없어서(`cmake`·SDL 없음), 펌웨어의 그리기 코드를 PC용으로 컴파일하고 ST7789 버스를 흉내 내 프레임버퍼를 PPM으로 저장하는 하네스를 만들었다.

```sh
P=platform.io
clang -std=gnu11 -w -DSIMULATOR -DDISPLAY_COLOR -DDISPLAY_240X320 -DKEYBOARD_3_KEYS \
  -DBUZZER -DVIBRATOR -DPULSE_LED -DALERT_LED -DGAME -DLANGUAGE='"ko"' \
  -DSTRINGS='"strings/ko.h"' \
  -DFONT_SMALL='"fonts/font_small_ko_color_21.h"' \
  -DFONT_MEDIUM='"fonts/font_medium_ko_color_32.h"' \
  -DFONT_LARGE='"fonts/font_large_color_84.h"' \
  -DFONT_SYMBOLS='"fonts/font_symbols_color.h"' \
  -I$P/lib/mcu-renderer -I$P/src docs/handoff/attachments/harness/harness.c \
  $P/lib/mcu-renderer/mcu-renderer.c $P/lib/mcu-renderer/mcu-renderer-st7789.c \
  $P/src/ui/draw.c $P/src/ui/measurements.c $P/src/ui/system.c \
  $P/src/system/cstring.c $P/src/system/cmath.c -lm -o /tmp/harness && (cd /tmp && ./harness)
```

- 실행한 폴더에 `overview-day.ppm`, `overview-night.ppm`, `overview-cpm.ppm`, `strings.ppm`이 생긴다.
- 하네스는 화면을 자홍색으로 먼저 칠한다. 결과에 자홍색이 보이면 그 자리가 빈틈이다.
- 하네스는 그리기 함수에 표본 문자열을 직접 넣는다. `instantaneous.c`의 뷰 로직(값 계산, 키 처리)은 거치지 않는다.
- 결과 예: `attachments/harness/overview-render.png`.

문법·타입만 볼 때는 같은 정의로 `clang -fsyntax-only`를 파일마다 돌린다. `-DDISPLAY_240X320`, `-DDISPLAY_240X320 -DVOICE`, `-DDISPLAY_320X240` 세 구성에서 경고 없이 통과했다.

## 확인하지 못한 것

- ARM 빌드, 링크, 바이너리 크기. 한국어 빌드가 `0x14000` 안에 들어가는지 모른다.
- 실기에서의 화면, 키 동작, 측정값.
- 영어 빌드에서 "Cumulative" 줄이 말줄임 되는지(한국어 빌드는 렌더링으로 확인했다).
- `DISPLAY_125PPI` 기기에서의 통합 화면. 좌표 계산만 했다.
- 레포트의 "확인하지 못한 의심" 여섯 건.
