## 바뀐 화면

설계: `docs/superpowers/specs/2026-11-13-fs5000-overview-redesign-design.md`, 계획: `docs/superpowers/plans/2026-11-13-fs5000-overview-redesign.md`, 승인 시안: `docs/mockups/overview-v4.html`.

- 측정 화면은 통합 화면 하나. 순간·평균·누적·추이 화면은 FS-5000에서 뺐다(코드는 다른 기기용으로 남아 있다).
- **1쪽**: 순간 선량률 54 px 숫자, 단위·신뢰구간, 로그 막대, 평균·최대·누적 선량·카운트, 시작·경과(14 px 한 줄), 쪽 표시 점.
- **2쪽**: 순간·평균·보조 단위 값(작게), 평균 시간·신뢰구간, 추이 그래프(가로선 값, 1·2·5 범위, 경고·경보선, 최신 값 점, 시간축).
- **상단 바**: 24 px, 14 px 글꼴. 측정 화면은 시각 + 평균 방식, 다른 화면은 제목 + 아이콘 + 시각.
- **키**: OK 짧게 = 쪽 전환, 2쪽에서 왼쪽·오른쪽 짧게 = 그래프 기간, 왼쪽 길게 = 순간·최대·평균 초기화(경보 해제가 먼저). 누적 선량 초기화는 설정 > 측정 > 누적 선량 > 초기화.
- **시작 시각**: 누적을 초기화한 시각을 설정 영역에 저장한다. 0은 "미설정"이고 `--`로 보인다. 시계가 설정되지 않은 상태에서는 시계를 맞추는 순간 기록되고, 그 전원 주기 안에서 시계를 더 고치면 같이 따라간다.
- **설정 저장**: 설정은 바뀔 때 1초 안에 저장된다(이전: 정상 종료 때만).

## 컨트롤러가 내린 판단 (사용자 확인 필요)

전체 목록과 근거는 아래 "판단 목록". 실기에서 특히 볼 것:

- **FIRMWARE_SIZE는 0x14000(81,920 B) 그대로다.** 한때 0x18000으로 올렸다가(R5) 되돌렸다(R17). 84 px 글꼴 제거, FS-5000 전용 21 px·14 px 글꼴에서 쓰이지 않는 글자 제외(R18)로 80,052 B에 맞췄다. 데이터 로그 공간은 원래와 같다.
- **설정 형식 버전**을 FS-5000만 `RadProK1`로 바꿨다. 이전 펌웨어의 설정·누적값은 읽지 않는다.
- FS-5000 전용 21 px 한국어 글꼴(`font_small_ko_fs5000_color_21.h`)을 따로 만들어 다른 기기의 한국어 글꼴은 그대로 두었다.

## 빌드·설치 (이 PC, Windows)

### 빌드

PlatformIO는 venv에 설치되어 있다.

```sh
cd platform.io
C:/Users/USER/.radpro-pio/Scripts/pio run -e bosean-fs5000-ko
```

- pio가 보여주는 Flash 퍼센트는 256 KB 기준이다. **FIRMWARE_SIZE(81,920 B)와는 직접 비교해야 한다.** 넘치면 `tools/sign.py`가 "input file too large"를 출력하고 그 이미지를 건너뛴다.
- `platformio.ini`는 `tools/build-env.py`가 만든다(`cd tools && python build-env.py`). FS-5000은 한국어 환경만 생성하도록 바꿨다.
- 다른 기기 환경은 코드를 지우지 않고 `build-env.py`의 `ENABLED_ENVS`(현재 `['bosean-fs5000']`)로 꺼 두었다. 다시 켜려면 이름을 목록에 추가하고 `build-env.py`를 다시 실행한다. 서명은 `sign.py`의 `ENABLED_BUILDS`(현재 `['bosean-fs5000-ko']`)에도 같은 이름을 넣는다. 다른 기기와 바이트 비교가 필요하면 두 목록에 잠시 넣는다.
- 원본(Gissio/radpro)을 받아올 때 `platform.io/platformio.ini`가 충돌하면 손으로 풀지 말고 그대로 두거나 어느 쪽이든 채택한 뒤, 병합 후 `bash tools/fs5000-postmerge.sh`를 돌린다. 이 스크립트가 `build-env.py`로 `platformio.ini`를 다시 만들고, FS-5000 글꼴 두 개 재생성, 깨끗한 빌드, 크기·글자·테스트 검사를 한 번에 한다. 어느 단계든 실패하면 거기서 멈추고 원인을 출력한다.

### 서명

```sh
cd build/radpro-3.1.1
python ../../tools/sign.py
```

현재 폴더 아래 `bosean-fs5000/firmware/radpro-bosean-fs5000-ko-<버전>.bin`이 생긴다. `ENABLED_BUILDS`에 없는 환경·언어는 조용히 건너뛴다.

### 설치

`build/radpro-3.1.1`은 릴리스 패키지(gitignore)이고 `lib/flashtool.bat`과 OpenOCD가 들어 있다. ST-Link를 SWD에 연결한 뒤:

```bat
cd build\radpro-3.1.1\bosean-fs5000
install.bat <서명된 이미지 절대경로>
```

- 먼저 현재 플래시 전체(256 KB)를 `build/radpro-3.1.1/backup/<번호>.bin`으로 백업하고, 그다음 mass erase 후 기록한다.
- 인자 없이 실행하면 언어 코드를 물어본다(대화형).
- `docs/install.bat`은 이 파일의 사본이고 혼자서는 동작하지 않는다(상대 경로 `..\lib\flashtool.bat`).

## 글꼴

- 의존성: `C:/Users/USER/.radpro-pio/Scripts/python -m pip install freetype-py bdflib` (PyPI 접속 가능).
- 원본 병합 후에는 `bash tools/fs5000-postmerge.sh`가 FS-5000 글꼴 두 개(`font_small_ko_fs5000_color_21.h`, `font_tiny_ko_color_14.h`)만 `build-fonts.py --fs5000-only`로 재생성하고, 이미지에 빠진 글자가 없는지와 `FS5000_UNUSED_KEYS` 문자열이 이미지에 다시 들어왔는지(원본이 기능을 켠 경우 — 목록에서 빼고 글꼴을 다시 만들어야 함)를 검사한다. 파이썬에 freetype-py, bdflib, pyelftools가 필요하다(`PYTHON`·`PIO` 환경 변수로 경로 변경).
- `tools/build-fonts.py`를 인자 없이 돌리면 전 언어 글꼴을 다시 만들고 오래 걸린다. FreeType 버전 차이로 다른 언어·다른 기기 글꼴이 바뀌므로 **새 글꼴 파일과 FS-5000 전용 파일만 남기고 나머지 변경은 되돌린다.**
- **14 px 글꼴(`font_tiny_ko_color_14.h`)은 화면 제목·평균 방식·2쪽 문구에 쓰이는 글자만 담는다.** 메뉴 제목이나 `drawTitleBar`/`drawNotification` 제목 문자열을 새로 추가하면 이 글꼴을 다시 만들어야 한다. 빠지면 그 글자가 비어 보인다. 도구가 소스에서 제목 문자열을 찾아 모으고, 못 찾으면 예외를 낸다.
- 새 문자열은 `platform.io/src/system/strings/*.h` 30개 파일 모두에 넣어야 빌드된다(ko·en만 번역, 나머지는 영어).
- FS-5000 글꼴 두 개는 글자를 줄여 0x14000에 맞췄다. `build-fonts.py`에 "14 px로만 그리는 문구" 목록과 `FS5000_UNUSED_KEYS`(이미지에 없는 문자열)가 있다. 문자열을 새로 쓰거나, 목록의 문구를 21 px로 그리게 바꾸거나, 지금 컴파일되지 않는 기능을 켜면 두 목록을 다시 확인한다.
- 빌드 후 `python tools/host/check-glyphs.py`로 이미지에 들어간 문자열의 글자가 모두 글꼴에 있는지 확인한다(사용법은 스크립트 첫머리). 단, 메뉴 제목처럼 14 px로 그리는 문자열을 14 px 글꼴 기준으로 검사하지는 않는다(남은 개선 과제).
- 남는 공간이 1,876 B뿐이다. 기능을 더하면 다시 넘칠 수 있다. 다음 수단은 14 px 글꼴 2bpp(약 5 KB 절약, 글자 가장자리가 조금 거칠어짐) 또는 FIRMWARE_SIZE 상향(데이터 로그 감소).

## PC 렌더링과 테스트

- `bash tools/host/render.sh`: WinLibs gcc로 그리기 코드를 PC용으로 빌드해 `tools/host/out/*.png`를 만든다. 화면을 자홍색으로 먼저 칠하고 그리므로, 출력의 `magenta=N`이 0이 아니면 빈틈이다. `strings` 사례는 일부만 그리므로 검사에서 뺀다.
- `bash tools/host/run-tests.sh`: `tools/host/test_*.c`를 빌드·실행한다. 첫 줄 `// SOURCES:`에 대상 소스를 적는다.
- 하네스는 그리기 함수에 표본 구조체를 넣는다. `measurements/overview.c`가 실제 측정값으로 구조체를 채우는 경로는 실기에서만 확인된다.

## 확인하지 못한 것

- 2쪽 그래프 라벨이 MCU 수학 라이브러리(qfp)에서도 PC와 같게 나오는지. 정수 기반 형식으로 바꿔 위험은 줄였지만 실기에서 µ 단위(0.05/0.1/0.2/0.5)를 확인할 것.
- 시계를 처음 맞출 때 시작 시각이 제대로 기록되는지(수정함, 실기 확인 필요. 설정 > 날짜 및 시간을 항목별로 바꿔 볼 것).
- 2쪽 그리기 시간(그래프 칸 201개마다 로그 계산).
- 2026-11-12 핸드오프의 미확인 항목(배터리 전압 ADC 등)은 그대로다.

## 릴리스

- 태그를 푸시하면 `.github/workflows/release.yml`이 빌드, 서명, zip 패키징을 하고 **초안** 릴리스를 만든다: `git tag 3.1.2 && git push origin 3.1.2`. 태그 이름은 `system.h`의 `FIRMWARE_VERSION`과 같아야 한다(다르면 실패). 초안의 내용을 확인한 뒤 GitHub에서 Publish 한다.
- 릴리스 노트는 `RELEASES.md`의 `## <버전>` 절에서 가져온다.
- 수동 실행(workflow_dispatch)은 릴리스를 만들지 않고 zip을 아티팩트로만 올린다.
- 원본 패키지(lib/, backup/, README.md, 설치 스크립트)는 Gissio/radpro 릴리스에서 받는다. 버전은 워크플로의 `UPSTREAM_TAG`(현재 `3.1.1`)로 바꾼다.
- 로컬에서 같은 zip 만들기(`radpro-3.1.1.zip`은 원본 릴리스 zip):

```
cd platform.io && pio run -e bosean-fs5000-ko && cd ..
mkdir package && cd package && python ../tools/sign.py && cd ..
python tools/package-release.py --upstream-zip radpro-3.1.1.zip --signed-dir package --version 3.1.2 --out build/radpro-3.1.2-bosean-fs5000-ko.zip
```
